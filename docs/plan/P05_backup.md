# P5. 세이브 내보내기/불러오기 — 클라우드 없는 백업 코드

> 웨이브 **W3** (모든 기능 파트가 main에 머지된 뒤 착수) · 규모 M · 담당 1명
> 의존: P3/P6/P7/P8이 `feat_*` 저장 키 규칙(규칙 3)을 지켜 머지되어 있을 것.

---

## 1. 목표

네트워크 없이(이 게임은 권한 0개) **"백업 코드" 텍스트 하나로 세이브 전체를 다른 기기로 옮기는** 기능.
설정 탭에서 「백업 코드 만들기」(코드 표시+클립보드 복사) / 「코드에서 불러오기」(클립보드 붙여넣기) 두 버튼을 제공한다.

## 2. 스토리 맥락

할머니의 수첩도 손으로 베껴 옮길 수 있듯, 플레이어의 수첩도 기기를 옮겨 다닐 수 있어야 한다.
"클라우드 없는 백업"은 이 게임의 철학(완전 오프라인·권한 없음)과 정확히 일치하는 기능이다.
README 로드맵에도 "클라우드 없는 백업(내보내기 코드)"로 이미 약속되어 있다.

## 3. 플레이어 경험

- 설정 탭 하단: 🗄 **백업 코드 만들기** → 화면에 긴 코드가 나눠 보이고(줄바꿈 청크), "클립보드에 복사" 버튼.
- **코드에서 불러오기** → 클립보드를 읽어 검증 후 복원. 잘못된 코드면 이유를 알려준다(손상/구버전/빈 클립보드).
- 복원 후에는 즉시 월드 상태·앨범·업적·스토리 진행·팬트리까지 전부 살아난다.
- 백업에는 게임 버전/생성 일자가 들어가고, 불러오기 시 현재 버전보다 새 버전의 코드는 경고 후 중단.

## 4. 소유 파일

### 새 파일 (전액 소유)

**`app/src/main/java/com/pizzaandbird/game/Backup.kt`** — `[P05]` KDoc.

```kotlin
// [P05] 백업/복원 — 기본 SharedPreferences 전체 덤프를 gzip+Base64+체크섬 코드로.
object Backup {
    const val MAGIC = "PBSAVE1"              // 코드 머리글 — 버전/포맷 식별
    fun export(ctx: Context): String         // 전체 user 세이브 → 사람이 나눠 읽을 수 있는 청크 텍스트
    fun import(ctx: Context, code: String): Result<String>   // 성공 시 요약 메시지, 실패 시 사유
}
```

포맷 설계 (권장):
1. **수집**: 기본 prefs(`SaveManager`와 같은 prefs — GameState.kt에서 PREFS 이름 확인 후 참조)의 `save`(기존 세이브 키) + `feat_*` 접두사 키 전부 → `JSONObject`로 덤프.
2. **직렬화**: JSON → UTF-8 → `Deflater`(java.util.zip) 압축 → `android.util.Base64` (URL_SAFE, NO_WRAP) 인코딩.
3. **봉투**: `MAGIC.` + `yyyyMMdd.` + 체크섬(Adler32, 8hex) + `.` + payload. 화면 표시는 8글자×줄 청크로 줄바꿈.
4. **복원**: 청크 공백 제거 → 머리글/날짜/체크섬 검증 → Base64 디코드 → Inflater → JSON → prefs에 기록(기존 값을 모두 지우지는 말고, 덤프에 있는 키만 덮어쓰기 + GameState가 쓰는 기존 키가 덤프에 없으면 그대로 둠) → 복원 직후 즉시 `SaveManager.load` 경로로 상태 리로드가 되어야 하므로 **현재 씬 리셋 절차**를 아래 패치와 함께 정의.

규칙:
- 외부 라이브러리 없음(프로젝트 철학). java.util.zip + android.util.Base64만 사용.
- 코드 길이 목표: 일반 세이브 기준 **8~20KB 텍스트** (수백 장 앨범이라도 압축되면 감당 가능). 넘치면 경고 표시(공유 앱 한계)만 하고 진행은 허용.

**`app/src/main/java/com/pizzaandbird/game/BackupOverlay.kt`** — `[P05]` KDoc.

- `Overlay` 서브클스. 두 모드:
  - 내보내기: 생성된 코드를 8글자 청크로 줄바꿔 표시 + 스크롤(손가락 드래그) + 「클립보드에 복사」 버튼(`ClipboardManager`, 권한 불필요).
  - 불러오기: 「클립보드에서 읽기」 버튼(`ClipboardManager` 읽기만) → `Backup.import` 결과 대화 표시 → 성공 시 "복원 완료! 게임을 다시 시작합니다" → 씬 리셋.
- 픽셀 UI에 텍스트 입력 필드가 없으므로 **클립보드 전용**으로 단순화 (수동 타이핑 입력 UI는 범위 밖).

### 패치 파일 (앵커 준수)

#### ① `GameState.kt` — companion 끝에 노출 함수 추가 (예산 15줄, **끝에 추가만**)
- 앵커: `object SaveManager`(또는 동등 이름) 블록의 **마지막 함수 직후 — 닫는 중괄호 직전**.
- 추가:
  ```kotlin
  // [P05] 백업 코드가 같은 prefs를 읽을 수 있도록 노출 — 기존 코드 무수정
  fun prefsName(): String = PREFS
  fun saveKey(): String = KEY
  ```
- 기존 `save/load/has/clear` 함수는 **절대 수정 금지** (세이브 포맷 변경 금지 — W3까지 다른 파트는 feat_* 키만 추가했으므로 호환 유지됨).

#### ② `Overlays.kt` — 설정 탭에 버튼 2개 (예산 20줄)
- 앵커: 설정 탭(`Tab.SETTINGS`) 본문을 그리는 함수 — 검색어 `resetArmed`(초기화 버튼 로직).
- 초기화 버튼이 있는 버튼 열의 **끝**에 2행 추가: 「🗄 백업 코드 만들기」「📥 코드에서 불러오기」→ `btnRects`에 등록, 액션은 `scene.openOverlay(BackupOverlay(scene, mode = ...))`.
- P9가 설정 탭에 글자 크기 버튼을 넣었을 것(W1) — **버튼을 목록 끝에 '추가'** 하는 방식이라 P9 버튼과 줄이 겹치지 않는다. 그래도 겹치면 **P5가 이긴다**(머지 순서 마지막이므로) — 충돌 시 양쪽 버튼 모두 유지로 해결.

#### ③ 복원 후 씬 리셋
- 성공 시 현재 상태를 리로드해야 한다. 가장 안전한 방법: `BackupOverlay`에서 성공 직후 `game`의 현재 씬을 종료하고 `TitleScene`으로 돌아간 뒤 "이어하기"를 자동 실행하는 흐름(기존 씬 전환/`fade` 패턴 준수). 이는 **신규 파일 낸에서 game API를 호출**하는 것으로 해결하고, `Game.kt`/`Scenes.kt`는 가능한 무수정. 꼭 1~2줄 훅이 필요하면 `Game.kt`에 함수 **끝에 추가**만(P9가 Game.kt를 패치하므로 — W3 시점 직렬이라 안전).

### 절대 건드리면 안 되는 것

- `save`/`load`의 JSON 스키마(마이그레이션 로직 포함) — 백업은 스키마를 모르는 **투명 덤프**여야 한다
- P3/P6/P7/P8의 저장 키명 (`feat_album_v1` 등) — 바꾸지 말고 수집만
- `AndroidManifest.xml` (권한 추가 금지 — 오프라인 원칙)
- res/raw, README.md

## 5. 테스트 / 검증

1. 빌드 + `kt_check.py` 통과.
2. 시나리오:
   - 플레이 진행(새 촬영/앨범/업적 해금/스토리 진행/피자 보유) → 백업 코드 생성 → **데이터 초기화**(설정 초기화 버튼) → 불러오기 → 전부 복원.
   - 손상 코드(임의 1글자 변경) → "코드가 손상됐어요" 계열 거부 + 기존 세이브 무손상.
   - 구버전 머리글 코드(`PBSAVE0.xxxx`) → "지원하지 않는 형식" 거부.
   - 빈 클립보드 → 안내 토스트.
   - 체크섬/날짜가 표시되는지(사용자가 최신 코드인지 구별 가능).
3. 두 에뮬레이터 간 코드 이동 수동 테스트(권장, 스크린샷).
