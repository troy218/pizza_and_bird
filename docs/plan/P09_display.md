# P9. 태블릿·폴더블 대응 & 글자 크기 접근성

> 웨이브 **W1** · 규모 M · 담당 1명
> 의존: 없음 (동시 착수 가능)

---

## 1. 목표

960×540 가상 해상도(16:9)로 짜인 게임이 **폴더블(펼침 ~4:3), 태블릿, 멀티윈도우 리사이즈**에서도
터치 박스와 화면 매핑이 정확하게 동작하게 하고, 설정에 **글자 크기(보통/크게/아주 크게)** 를 추가한다.
스토어 등록 전 필수 품질 게이트이기도 하다(P10과 연동 — 폴더블 지원 여부는 Play listing 체크 항목).

## 2. 스토리 맥락

이 게임의 플레이어는 이불 속에서, 소파에서, 태블릿 거치대 앞에서 플레이한다.
"할머니의 낡은 수첩"을 닮은 UI가 작은 화면 바깥에서 깨지는 순간 몰입은 사라진다.
힐링 게임의 접근성은 기능이 아니라 **매너**다 — 천천히 읽는 사람에게도, 손끝이 굵은 사람에게도 같은 따뜻함을.

## 3. 플레이어 경험

- 폴더블 펼침 화면(초기: 거의 정사각)에서도 화면이 찌그러지지 않고, 터치한 곳과 게임 내 좌표가 일치한다.
- 멀티윈도우로 창 크기를 바꿔도 크래시·상태 소실 없이 계속 플레이된다.
- 설정에 🔠 **글자 크기** (100%/115%/130%) — 대화상자·메뉴·도감 텍스트가 커진다 (월드 픽셀 아트 스케일은 그대로).
- D패드/버튼 크기도 화면 높이 비례로 살짝 커진다(작은 폰에서 이미 검증된 범위 내).

## 4. 소유 파일

새 파일 없음 — **아래 파일들은 이 파트의 전용 패치 대상**(W1: 다른 파트가 건드리지 않는다):

| 파일 | 작업 | 변경 예산 |
|---|---|---|
| `AndroidManifest.xml` | `android:resizeableActivity="true"`, `configChanges` 점검(`screenSize|screenLayout|smallestScreenSize|orientation|keyboardHidden` — 게임 루프 재시작 없이 리스이즈 흡수) | 5줄 |
| `Game.kt` | 스케일링 계산 보강: aspect가 16:9보다 **정사각형에 가까우면 상하 레터박스**, 더 **넓으면 좌우 필라박스**로 일원화 + `screenToVirtual` 매핑이 이 레터박스 오프셋을 반영하는지 검증·수정 | 60줄 |
| `GameView.kt` | surfaceChanged/리사이즈 경로 확인 — 뷰 재생성 시 루프·상태 안전 복귀 | 20줄 |
| `Input.kt` | D패드·버튼 크기를 `min(virtW, virtH)` 비례 계수로 상수화(기존 px 고정값 유지 폴더), 터치 매핑에 레터박스 오프셋 반영 여부 최종 확인 | 30줄 |
| `Hud.kt` | HUD 패널이 좁은 폭에서 겹치지 않도록 최소 너비/줄바꿈 가드(960×540 가상좌표라 큰 재작업 아님 — **검증 위주**) | 20줄 |
| `UiKit.kt` + `Type.kt` | 텍스트 스케일 전역 계수 `TypeScale.of(ctx): Float` (기본 1.0, 옵션 1.15/1.3) — Type 역할(제목/본문/캡션) 정의는 무수정, **그리기 진입점 1곳에 계수 곱** 방식으로 일괄 적용 | 40줄 |
| `Overlays.kt` | 설정 탭에 글자 크기 버튼 1개 추가 (예산 12줄 — 아래 앵커) | 12줄 |

### 설정 저장 (규칙 3 준수 — GameState 무수정)

- 글자 크기 선택은 기본 prefs 키 **`feat_display_v1`** 에 저장한다 (기존 음악/효과음 설정은 GameState 소속이라 건드리지 않는다 — 새 설정은 새 키).
- `TypeScale.of(ctx)`가 이 키를 읽는다.

### 패치 앵커 (정확한 위치)

#### ① `Overlays.kt` — 설정 탭 글자 크기 버튼
- 앵커: 설정 탭 본문에서 음악/효과음 토글이 그려지는 지점 (검색어 `resetArmed`면 같은 함수; 근처에 토글이 있음).
- 토글 행 바로 **다음 줄**에 `btnRects` 항목 1개 추가: 「🔠 글자 크기: 보통 / 크게 / 아주 크게」(탭할 때마다 순환, `feat_display_v1` 저장, 즉시 반영).
- ⚠️ 같은 설정 탭을 P5가 **W3**에 버튼을 추가한다 — P9는 "토글 근처 상단", P5는 "목록 끝"에 넣는 규칙으로 분리되어 있고 시기도 직렬이라 충돌하지 않는다. 충돌 리포트 시 양쪽 다 유지로 해결.

#### ② `AndroidManifest.xml` — 액티비티 속성
- 앵커: `<activity android:name=".MainActivity"` 태그.
- 속성 추가/확인만 — 다른 속성·권한 변경 없음 (권한 0개 원칙 유지).

### 절대 건드리면 안 되는 것

- 가상 해상도 **960×540 자체는 유지** — 모든 씬/오버레이 좌표계 재작업을 막는 결정적 범위 제한. 폴더블 정사각 화면에서 생기는 영역은 레터박스(테두리 감성 유지: 도트 무늬/칠판 느낌의 안쪽 여백 허용하되 필수 아님).
- `WorldScene.kt`, `HomeScene.kt` 등 씬 로직 전부
- `Assets.kt`, `Audio.kt`
- 가로 모드 강제 정책(`screenOrientation`이 있다면 그대로 유지 — 세로 모드 지원은 v0.5 과제로 명시하고 범위에서 제외)

## 5. 테스트 매트릭스 (필수 — 결과 표를 PR에 첨부)

| 구성 | 화면 비율 | 확인 항목 |
|---|---|---|
| 폰 16:9 (기준) | 1.78 | 회귀 없음 (기존과 픽셀 단위 동일) |
| 폰 19.5:9 / 20:9 | ~2.0~2.22 | 좌우 필라박스, 터치 매핑 정확 |
| 폴더블 펼침 (Fold 에뮬) | ~1.0~1.2 | 상하 레터박스, D패드/버튼 터치 정확 |
| 태블릿 10" | 1.6 (4:3도) | 텍스트 가독성, 터치 매핑 |
| 멀티윈도우 (한쪽 40%) | 가변 | 리사이즈 중 크래시 없음, 다음 프레임부터 스케일 재계산 |
| 글자 크기 크게/아주크게 | — | 대화상자 줄넘김 깨짐 없는지 (긴 대사 샘플로) |
| 글박줄 깨짐 체크 | — | 메뉴 탭 라벨·버튼 라벨이 상자 안에 들어오는지 |

- 에뮬레이터: Fold 7.6"/Pixel Tablet 10" 프로필 권장. 실기기가 없으면 에뮬 스크린샷으로 대체.
